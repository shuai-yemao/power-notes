# FreeRTOS 任务设计：先定义边界，再谈并发

任务不是把函数丢进调度器就结束了。真正需要先说清楚的，是状态由谁拥有、什么时候被唤醒，以及失败之后系统还能否继续工作。

## 先说清状态与所有权

我倾向于把任务看成状态的拥有者，而不是函数的集合。任务拥有自己的上下文、队列和工作缓存；其他模块通过消息或公开接口表达意图，不直接摸它的内部变量。

> 并发安全的第一步，不是加锁，而是减少需要同时拥有同一份状态的地方。

## 把唤醒条件写出来

每个任务都应该能用一句话回答：它在等待什么？消息、事件、时间点，还是外部中断？这句话会直接影响同步原语的选择，也决定了最大响应时间是否可估计。

```c
for (;;) {
    wait_for_event(timeout);
    process_owned_state();
    publish_result();
}
```

## 失败路径不是附录

队列满、超时、驱动不可用、初始化中途失败，都应回到任务自己的状态机中。记录稳定错误码，保留重试或降级出口，才能让系统在能力不可用时仍然可观察、可恢复。
